# AMP镜像独立发布约定

状态：2026-09-10本地收尾方案。独立仓尚未创建，没有公开下载地址，
也没有自动发布或CI下载任务。本文件不授予第三方组件的再分发许可。

## 仓库边界

团队仓保留openvela适配、协议、客户端和自有服务端源码、构建配置/脚本、
验证方法及镜像版本引用。未来独立镜像仓负责构建编排、依赖固定、
发行附件、对应源码和第三方许可证材料。无需把Linux源码混入Apache BSP目录。

独立仓可为我们有权授权的新脚本选择许可证，但不能给整个混合镜像统一换证。
Linux、BusyBox、C运行库、RKNN和启动固件分别保留原许可证及版权声明。
本地测试通过与有权公开分发是两个独立门槛。

## 接入方式

第一阶段推荐手动下载固定版本FIT，核验SHA256，按SLOT_BOOT.md刷AMP槽。
README链接到实际发布页、版本清单和刷写说明即可，不强制公共CI下载二进制。
不得只写一句“自行下载”而省略兼容版本、校验值和恢复方式。

后续CI可以显式接收已准备好的本地FIT，也可以下载固定Release附件；
两种输入使用同一份固定版本/大小/SHA256/ABI清单。禁止隐式取latest，
下载或校验失败不得回退到旧缓存冒充本次产物。下载URL确定后再实现接入。

现有AMP FIT已经包含Linux Image、DTB、initramfs和openvela固件。
直接调取成品FIT时，必须同时固定其内嵌openvela版本，不能说它包含本次CI
刚编译的openvela。需要组合本次构建时，镜像仓改为提供固定Linux组件包，
由团队CI调用已有build_amp_fit.sh重新打包并验证配套ABI、内存布局和配置。
这两种形式不得混淆；目前只验证了完整FIT。

## 每个正式版本的最小材料

- 不可变版本号、FIT及SHA256；板型、SD/eMMC介质、bootamp ABI、协议版本。
- 团队仓/NuttX补丁/N-Boot/Linux/SDK的准确版本、构建配置和工具链版本。
- 组件清单和许可证原文；按各组件条款提供对应源码、补丁、配置及构建材料。
- 刷入AMP槽、试启动、确认和回退步骤；明确不能写入普通nuttx_a/b。
- 与该FIT哈希匹配的板测记录；不能借用旧镜像冷启动结果。

当前工作树未提交，不用某个旧HEAD冒充当前镜像的完整源码版本。
公开发行前需先整理单一职责提交、固定源码快照并重建验证。

## 分发检查（当前未全部完成）

| 组件 | 当前来源 | 公开发布前需要的材料 |
|---|---|---|
| openvela/自有nyamp代码 | 团队源码及NuttX补丁 | 保留原许可证，固定完整源码版本 |
| Linux及rknpu驱动 | K7 SDK b553a938的kernel-6.1 | 对应内核源码、变更、配置和构建材料；逐文件保留许可 |
| BusyBox | Debian busybox-static 1.37.0-6+b8 arm64 | 对应源包、Debian补丁/配置/构建材料及GPLv2文本 |
| libc/loader等 | AArch64 Debian交叉运行库 | 固定软件包版本，分别核对LGPL等条款及源码材料 |
| libstdc++/libgcc | GCC交叉运行库 | 固定版本，保留适用许可证与运行库例外文本 |
| librknnrt.so | rknn-toolkit2 v2.3.2 | 核实具体二进制再分发授权，根LICENSE不足以在本次核查中确认 |
| N-Boot/DDR/BL31/OP-TEE等 | 单独配套启动器 | 独立记录各组件来源与授权，不并入AMP整包统一换证 |

若暂不能确认RKNN再分发权，就不由我们发布含该库的整包；可以仅提供自有
构建脚本，由使用者按厂商条款自行取得SDK后本地构建。即便由独立仓发布，
我们发布含第三方二进制的镜像时仍需履行相应义务。仅链接厂商官方发行物
与由我们另起仓库托管自己的整包，是不同的分发方式。
